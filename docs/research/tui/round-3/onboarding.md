## 9. Risks

1. **P1 changes live behaviour for round-2 users today**: a file or env `mode: jev-on` that was silently ignored by the session will now start the LLM (with the $2.00 cap that `jevcode config` already reported). Announce it in the CHANGELOG; the caps item (P8) makes the money visible on the first keyed start too if the owner wants it there (I kept it to wizard saves to avoid a new line on every start).
2. **Cost of the default flip**: a keyed `OPENROUTER_API_KEY` user who never asked for an LLM now pays GLM on every run ($2.00 / $10.00 caps). The `options` `3` path and the P8/P9 copy are the mitigations; a louder one is a one-time `[setup] mode jev+llm by default now — /mode jev-only keeps the round-2 behaviour` item on the first start after the upgrade (needs a "seen" marker in `~/.jevcode`; not proposed, flagged).
3. **Verification sends a priced request** only on `y` — but `login --verify` in CI would call the network; that is today's contract.
4. **The generator 1-token call's latency is unmeasured**; the 5 s timeout bounds it. Measure once live before shipping the copy `under $0.0001`.
5. **`llm+jev · verified` as a badge word** is 18 cells; the console top edge at 60 columns (`╭─ <badge> · next run ──── <dir> ─╮`) will truncate the directory first; the flat tier drops the badge before `help` (§1.5). Check `round2-console.test.tsx` frames at 12×60.
6. **Copy churn across ~30 test files**: the re-pin is mechanical but wide; do it in the second commit with `DEFAULT_MODE`-derived expectations so a later flip to `llm-jev` moves nothing.
