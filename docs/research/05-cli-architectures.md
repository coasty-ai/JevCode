### 1.2 Entry file and the two-process startup trick (`packages/cli/index.ts`)
- `index.ts` is a **lightweight parent**: it imports only `node:child_process`, `node:os`, `node:v8` and `./src/utils/processUtils.js`, then `spawn(process.execPath, spawnArgs, { stdio: ['inherit','inherit','inherit','ipc'] })` re-launching itself with `--max-old-space-size=<50% of RAM>` when the current heap limit is lower. Verbatim comment: `// We avoid importing heavy dependencies here to save ~1.5s of startup time.` The child path does `const { main } = await import('./src/gemini.js')`. Relaunch loop keyed on `RELAUNCH_EXIT_CODE` (= `199` in `src/utils/processUtils.ts`); the child is marked with env `GEMINI_CLI_NO_RELAUNCH: 'true'`; `SANDBOX` env also skips the parent path. (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/packages/cli/index.ts ; .../packages/cli/src/utils/processUtils.ts, fetched 2026-09-19)
- `src/gemini.tsx` `main()`: loads settings/trusted folders, `loadSandboxConfig` -> if sandboxing enabled and not inside, `if (!process.stdin.isTTY) stdinData = await readStdin()` then `relaunchOnExitCode(() => start_sandbox(...))`; otherwise `registerTelemetryConfig(config)`, sets raw mode only `if (config.isInteractive() && !wasRaw && process.stdin.isTTY)`, collects `startupWarnings` (`utils/startupWarnings.ts` reads `os.tmpdir()/gemini-cli-warnings.txt`), and finally either `startInteractiveUI(...)` (which lazily does `await import('./interactiveCli.js')`) or, `if (!process.stdin.isTTY) stdinData = await readStdin()` -> `runNonInteractive(...)`. Error if `--prompt-interactive` is combined with piped stdin: "The --prompt-interactive flag cannot be used when input is piped from stdin." (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/packages/cli/src/gemini.tsx, fetched 2026-09-19)
- `src/deferred.ts`: yargs subcommands (e.g. `mcp`) are registered but their handler is deferred until settings/admin policy are loaded (`setDeferredCommand` / `runDeferredCommand`). (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/packages/cli/src/deferred.ts)

Wrapped in providers `SettingsContext`, `MouseProvider`, `SessionStatsProvider`, `VimModeProvider`, `KeyMatchersProvider`, `KeypressProvider`, `ScrollProvider`, `TerminalProvider`, `OverflowProvider`. Other components: `LoadingIndicator`, `StatusDisplay`, `DialogManager`, `Notifications`, `ToolConfirmationQueue`, `SessionBrowser`, `DebugProfiler` (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/packages/cli/src/ui/components/{Composer,Footer}.tsx ; https://api.github.com/repos/google-gemini/gemini-cli/contents/packages/cli/src/ui/components).

### 1.4 Bundling (`esbuild.config.js`, root)
- `baseConfig = { bundle: true, platform: 'node', format: 'esm', external: ['@lydell/node-pty', 'node-pty', ...node-pty platform pkgs, '@github/keytar'], loader: { '.node': 'file' } }`; `cliConfig`: `entryPoints: { gemini: 'packages/cli/index.ts' }`, `outdir: 'bundle'`, **`splitting: true`** (so dynamic `import()`s become separate chunks -> lazy loading really is lazy), `metafile: true`, `define` for `process.env.CLI_VERSION`, `NODE_ENV`, plus a `banner.js` that defines `require` (via `createRequire(import.meta.url)`), `__chunk_filename` and `__chunk_dirname`, with `define: { __filename: '__chunk_filename', __dirname: '__chunk_dirname', ... }` mapping the CJS globals onto them (also defines `process.env.GEMINI_SANDBOX_IMAGE_DEFAULT`). Aliases: `is-in-ci` -> `packages/cli/src/patches/is-in-ci.ts`, `https-proxy-agent`/`http-proxy-agent` patches. A second build emits Ink's `worker/worker-entry.js`. (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/esbuild.config.js, fetched 2026-09-19)
- `patches/is-in-ci.ts` verbatim: "This is a replacement for the `is-in-ci` package that always returns false. We are doing this to avoid the issue where `ink` does not render the UI when it detects that it is running in a CI environment." (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/packages/cli/src/patches/is-in-ci.ts)
- Root `package.json` scripts: `"bundle": "... node esbuild.config.js && node scripts/copy_bundle_assets.js"`, `"build:binary": "node scripts/build_binary.js"` (Node SEA), `"test:perf": "vitest run --root ./perf-tests"`, `"test:sea-launch"`. Root `bin: { gemini: 'bundle/gemini.js' }` (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/package.json).
- Single-executable path: `sea/sea-launch.cjs` uses `require('node:sea').getAsset(...)`; `scripts/build_binary.js` runs `npm run bundle` (whose `scripts/copy_bundle_assets.js` globs `packages/**/*.sb` into `bundle/`), copies the host-platform ripgrep from `packages/core/vendor/ripgrep` into `bundle/vendor/ripgrep/`, then writes a generated `sea-config.json` whose `assets` map `manifest.json`, `gemini.mjs` (= `bundle/gemini.js`), every other `bundle/*.js` chunk, each `.sb` file and staged native modules (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/sea/sea-launch.cjs ; .../scripts/build_binary.js).

### 1.6 Sandboxing
- `packages/cli/src/utils/sandbox.ts`: `if (config.command === 'sandbox-exec')` -> `SEATBELT_PROFILE ??= 'permissive-open'`, profile file `sandbox-macos-${profile}.sb`, passes `-D` INCLUDE_DIR params, sets `SANDBOX=sandbox-exec` in child env; container path supports `docker`, `podman`, `runsc` (`docker --runtime=runsc`), optional `GEMINI_SANDBOX_PROXY_COMMAND`. Verified profile files in `packages/cli/src/utils/`: `sandbox-macos-{permissive,restrictive,strict}-{open,proxied}.sb` (6 files) plus `sandboxBuiltinProfiles.ts` (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/packages/cli/src/utils/sandbox.ts ; https://api.github.com/repos/google-gemini/gemini-cli/contents/packages/cli/src/utils, fetched 2026-09-19).
- `sandbox-macos-permissive-open.sb` starts `(version 1)` ... `(deny default)` `(allow file-read*)` `(allow process-exec)` `(allow process-fork)` and a Chromium-derived `sysctl-read` allowlist (`(allow sysctl-read (sysctl-name "hw.activecpu") ...)`, with a comment citing `source.chromium.org/.../sandbox/policy/mac/common.sb;l=273-319`) (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/packages/cli/src/utils/sandbox-macos-permissive-open.sb, fetched 2026-09-19).
- Docs: enable via `-s`/`--sandbox`, `GEMINI_SANDBOX=true|docker|podman|sandbox-exec|runsc|lxc`, or settings `"tools": {"sandbox": "docker"}`; "Default profile: `permissive-open` - denies operations by default"; Windows native sandbox and gVisor sections exist (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/cli/sandbox.md).

## 2. Codex CLI (openai/codex)

### 2.1 History: TypeScript+Ink -> Rust+ratatui
- Announcement: GitHub Discussion #1174 "Codex CLI is Going Native" by `fouad-openai`, 2025-05-30. Stated reasons (quoted): zero-dependency install — "currently Node v22+ is required, which is frustrating or a blocker for some users"; native security bindings — "already ship a Rust for linux sandboxing since the bindings were available"; optimized performance — "no runtime garbage collection, resulting in lower memory consumption"; extensible protocol — "a 'wire protocol' for Codex CLI to allow developers to extend the agent in different languages". (https://github.com/openai/codex/discussions/1174, fetched 2026-09-19). Note: the announcement cites install friction, sandbox bindings and memory — **not** startup latency — as the drivers.
- TS removal commit: `408c7ca142689136d887676def1bf41ea80bb2a9` by Michael Bolin, Fri 2025-08-08 16:09 -0700, "chore: remove the TypeScript code from the repository (#2048)" — "This deletes the bulk of the `codex-cli` folder and eliminates the logic that builds the TypeScript code and bundles it into the release." (https://github.com/openai/codex/commit/408c7ca14268.patch, fetched 2026-09-19).
- Old Ink app (at commit `cabf83f2ede2`, 2025-05-16): `codex-cli/package.json` deps `ink ^5.2.0`, `react ^18.2.0`, `meow ^13.2.0`, `openai ^4.95.1`, engines `node>=22`; `build.mjs` used esbuild with an `ignore-react-devtools` plugin (Ink's `react-devtools-core` import is "ESM-unfriendly") and produced `dist/cli.js` (dev shebang `#!/usr/bin/env -S NODE_OPTIONS=--enable-source-maps node`). `src/components/chat/terminal-chat.tsx` (default export `TerminalChat`, owns `AgentLoop`, `approvalPolicy` state, `TerminalChatInput`, `TerminalMessageHistory`); `terminal-message-history.tsx` rendered `<Static items={["header", ...messages]}>` — i.e. the same `<Static>` transcript pattern; `src/cli.tsx` used `meow`, `--quiet` non-interactive mode (`runQuietMode`), approval modes `suggest | auto-edit | full-auto`, `--full-auto`; sandbox: `src/utils/agent/sandbox/macos-seatbelt.ts` (`PATH_TO_SEATBELT_EXECUTABLE = "/usr/bin/sandbox-exec"`, `READ_ONLY_SEATBELT_POLICY` starting `(deny default)`/`(allow file-read*)`) and `landlock.ts` invoking prebuilt `codex-linux-sandbox-x64|arm64`. README then: "macOS 12+ - commands are wrapped with Apple Seatbelt (sandbox-exec)"; "Linux - there is no sandboxing by default. We recommend using Docker". (all at https://raw.githubusercontent.com/openai/codex/cabf83f2ede2e67d12d33a6cf38f16b1225e8d1d/..., fetched 2026-09-19)

Requirements: "macOS 12+, Ubuntu 20.04+/Debian 10+, or Windows 11 via WSL2", RAM "4-GB minimum (8-GB recommended)" (https://raw.githubusercontent.com/openai/codex/main/docs/install.md, fetched 2026-09-19).

- TUI: crate `codex-tui`, `ratatui = "0.30.2"` (features `crossterm`), `crossterm = "0.29.0"` but `[patch.crates-io]` points it at `https://github.com/openai-oss-forks/crossterm` rev `45fecb9508105988f42fe6ff0441783ed3717f92`, `tokio`. `tui/src/main.rs` -> `clap` `TopCli` -> `run_main(...)`. ### 2.3 Sandbox and approvals (Rust)
- macOS: `codex-rs/sandboxing/src/seatbelt.rs` — `MACOS_PATH_TO_SEATBELT_EXECUTABLE = "/usr/bin/sandbox-exec"`, policies via `include_str!("seatbelt_base_policy.sbpl")`, `seatbelt_network_policy.sbpl`, `seatbelt_preferences_policy.sbpl`, `seatbelt_read_only_platform_defaults.sbpl` (https://raw.githubusercontent.com/openai/codex/main/codex-rs/sandboxing/src/seatbelt.rs).
- Linux: `codex-rs/linux-sandbox` (deps `landlock`, `seccompiler`); `landlock.rs` header: "In-process Linux sandbox primitives: `no_new_privs` and seccomp. Filesystem restrictions are enforced by bubblewrap in `linux_run_main`. Landlock helpers remain available here as legacy/backup utilities." ## 5. Adopt / Reject for JevCode

**Adopt**
1. `<Static>` transcript + non-static pending region (Gemini `MainContent.tsx`; old Codex `terminal-message-history.tsx`; Codex-Rust's `insert_history.rs` is the same idea in ratatui) — proven pattern in all three lineages.
2. Single ESM bundle via esbuild `bundle:true, platform:'node', format:'esm', splitting:true` with `.node`/pty packages external (Gemini `esbuild.config.js`); publish `bin -> bundle/jevcode.js` with `dependencies: {}` like Gemini/Claude 2.1.89.
3. Dependency-free entry file that does `await import()` of the heavy app; parse argv, detect `process.stdin.isTTY`, and start the Ink render before any network call (Gemini `index.ts` "~1.5s" comment; issues #21853/#25757).
4. `module.enableCompileCache()` at the top of the entry (Node ≥22.8.0, non-throwing, env-overridable) — free win since JevCode already targets Node 22+ (Ink 7 requires `node>=22`).
5. Non-interactive runner selected by `!process.stdin.isTTY` / `-p`, with `--output-format text|json|stream-json` (Gemini) or JSONL events (`codex exec --json`) — required for SWE-bench/Terminal-Bench harness runs.
6. Telemetry off by default and lazily imported (Gemini `GEMINI_TELEMETRY_ENABLED` default `false`; dev.to notes Claude lazy-loads OTel/gRPC); never probe hardware (`systeminformation`) at startup.
7. Sandbox by shelling out: `/usr/bin/sandbox-exec` with a `(deny default)` SBPL profile on macOS (Gemini `.sb` files, Codex `seatbelt.rs`), `bwrap` on Linux (Codex bwrap, Claude Code + `@anthropic-ai/sandbox-runtime` `srt`), gated behind explicit modes like Codex `read-only|workspace-write|danger-full-access`.
8. Statusline/hook contracts as JSON-on-stdin commands with exit-code semantics (Claude Code statusline 300 ms debounce; hooks exit 0/2) — cheap to implement, benchmark-friendly.
9. A `perf-tests`-style cold-start baseline (Gemini: 927.6 ms baseline, 15% tolerance) plus `node --cpu-prof` in CI.
10. Alias `is-in-ci` -> `false` in the bundle so Ink renders under CI/tmux harnesses (Gemini patch; issue #1563 referenced there).

**Reject**
1. Full Rust/ratatui rewrite — Codex's stated motives were Node-install friction, sandbox bindings and memory, not UI speed (#1174); JevCode's value is the Jev decision loop, not the renderer.
2. Bun as a runtime/compiler dependency — Claude Code's Bun path shipped a 59.8 MB `.map` (2.1.88 unpublished) and a ~500 MB binary per platform (`install.cjs`); JevCode has no distribution problem that justifies this.
3. Node `--build-snapshot` for the app — snapshots load "a single entrypoint ... not additional user-land modules" (Node CLI docs), so it cannot include Ink/React.
4. Forking Ink (Gemini uses `npm:@jrichman/ink@6.6.9`) — stay on upstream `ink@7.1.1` (already has `alternateScreen`, `incrementalRendering`, `maxFps`).
5. Docker/Podman as the default sandbox (Gemini `GEMINI_SANDBOX=docker`) — slow to start and unavailable on the benchmark runners; keep as optional.
6. Alternate-screen-by-default (Codex Rust `auto` -> alt screen) — Codex needed a custom `insert_history` escape-sequence path to preserve scrollback; Ink `<Static>` in the main buffer gives scrollback for free.
7. Startup-time network probes (experiments, quota, GPU info, editor discovery) — every Gemini startup regression in §1.7 came from one of these.
8. A Node SEA binary for v1 — SEA is Stability 1.1 and Gemini needs a custom `sea-launch.cjs` asset extractor; revisit only if `npm i -g` proves a blocker.
